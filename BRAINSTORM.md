## Контекст (зачем это вообще Дмитрию)

- Конкурс: `PROJECT.md` в этом репо — официальный AI-agent contest от самого «Потока» (events.potok.io/ai_agent_hr_contest), дедлайн **6 сентября 2026**. Обязательное условие — open source, права остаются у автора.
- Дмитрий работает в «Потоке» вторым/неполным местом (параллельно с основной работой в Optimacros), роль — скорее AI-оркестрация/QA, не хардкорная разработка продукта. Core-продукт «Потока» — именно эта рекрутинговая ATS-платформа (раньше это не было подтверждено, подтвердилось через чтение `docs/`).
- Общая карьерная рамка (2026): «AI Orchestrator» — найти домен, которым не владеешь → построить AI-пайплайн → показать видимый результат → забрать домен. Уже обкатано на SEO-домене в Optimacros (сработало технически, но результат нигде публично не залогирован — известная дыра).
- Почему именно этот конкурс интересен отдельно от общей рамки: он снимает IP-конфликт, который обычно блокирует любые «Поток»-смежные идеи (сама компания официально разрешает и требует публикацию), и даёт готовый бесплатный контур видимости (демо-день, витрина) — то, чего не хватило SEO-домену в Optimacros.
- Ограничение по времени: конкурс жёсткий (~3 недели на момент обсуждения), нужна узкая, а не масштабная идея.

## Рассмотренные направления

### 1. HR-домен «в лоб» (вакансии/кандидаты через API «Потока»)
- **Funnel SLA watchdog** — мониторинг `ajs_joins`/`events_stream`, алерт, если кандидат завис на этапе дольше порога (Рецепты 6, 8 из `docs/13-recipes.md`). Прямое попадание в категорию «HR-аналитика», минимум discovery cost (документация уже всё даёт).
- **Vacancy SEO/content agent** — аудит и переписывание текста вакансий на конверсию (Рецепты 1, 9, Jobs + Career API). Сильный кандидат именно как публичный кейс-пруф для отдельного (не связанного с «Потоком») плана — офер контент-опс/SEO для малого бизнеса, который Дмитрий сейчас выстраивает. Слабее для самого конкурса по оригинальности.
- **Resume quality checker** — рассмотрели и отклонили: это самая очевидная HR-tech идея (много конкурентов на конкурсе будут делать что-то похожее), и она не подходит как кейс под контент-опс/SEO-офер (аудитория не совпадает — резюме пишет кандидат, не малый бизнес-клиент).

### 2. Перенос архитектуры из уже реализованных личных проектов на API «Потока»
Смотрели: `~/www/repos/odor` (Нюхослав), `~/www/repos/meet`, `~/www/repos/intercom`, `~/www/repos/holotek`.

- **Нюхослав (odor) → Funnel SLA Watchdog.** Архитектура переносится почти один в один: поллер по расписанию → риск-скор по порогу → Telegram-алерт с inline-кнопками → recovery-check. Меняется только источник данных (AIS+ветер → `ajs_joins`/`events_stream`) и текст алерта. Минимум нового кода, максимальная воспроизводимость (только токен API + токен бота, никакого железа).
- **Meet → Interview Intelligence Agent.** Локальная транскрипция + диаризация + summary уже работают. Новое — только мост в «Поток»: пушить итог интервью как комментарий в карточку кандидата (Рецепт 5, `POST /api/v2/events`) и/или прикреплять транскрипт как документ (Рецепт 12). Самая оригинальная идея (мало у кого есть готовый локальный ASR-конвейер), но слабее по воспроизводимости — нужен Mac + whisper.cpp + сам `meet`.
- **Intercom → слабо клеится.** Это открывание двери конкретного вендора (Sputnik/Gorod) для одной квартиры; натянуть на «онбординг → доступ в офис» можно только фиктивно.
- **Holotek → почти не клеится.** CO₂-датчик по USB, нет точки соприкосновения с API «Потока» кроме искусственной привязки к well-being.

**Вывод по разделу 2:** реальный выбор — между Нюхославом (меньше кода, выше воспроизводимость, но по сути та же funnel-аналитика из раздела 1) и Meet (минимум нового, максимум оригинальности, но выше порог входа для того, кто запускает).

### 3. Переобозначение сущностей API (остаёмся в HR, но не «наём»)
Инсайт: `AJS Join` — это generic движок «сущность идёт по настраиваемым этапам», вакансия/кандидат — просто одна конкретная обёртка сверху. Ранжировано по тому, насколько естественно ложатся поля:

1. **Онбординг** — `Job` = программа адаптации, `Applicant` = новый сотрудник, этапы = шаги адаптации. Прямая категория конкурса, поля ложатся почти без трения.
2. **Оценка сотрудников / performance review** — `Job` = цикл оценки, `Applicant` = сотрудник, этапы = самооценка → оценка руководителя → калибровка → фидбек. Тоже прямая категория, поля ложатся хорошо.
3. **Обучение / наставничество** — `Job` = учебная программа/когорта, `Applicant` = стажёр/менти, этапы = модули курса.
4. **Внутренняя мобильность / кадровый резерв** — буквально тот же смысл (вакансия/кандидат), просто воронка внутренняя, а не внешняя. Меньше всего переосмысления.
5. **Отпуска/больничные как воронка согласования** — слабый вариант, поля вакансии/кандидата плохо ложатся на заявку на отпуск.

### 4. Полный отказ от HR-домена
Рассмотрели и закрыли как тупиковую ветку по двум причинам:
1. Конкурс требует именно HR-задачу (критерий №1 в условиях, весь список категорий — HR).
2. Даже вне конкурса не имеет практического смысла: «Поток» — платная рекрутинговая SaaS конкретной компании, никто не заведёт там фейковые «вакансии», чтобы на самом деле вести продажи или тикеты поддержки — это ломает критерий «воспроизводимость» (реальный пользователь так не поступит).

## Текущий статус решения

Ничего не выбрано. Открытые варианты на столе (от простого к сложному):
- Funnel SLA Watchdog (одинаково всплывал в разделах 1 и 2, вероятно самый безопасный выбор по срокам/воспроизводимости)
- Interview Intelligence Agent (Meet → Поток) — самый оригинальный, но с более высоким порогом входа для проверяющих
- Vacancy SEO/content agent — сильнее как внешний кейс-пруф под отдельный план (контент-опс/SEO офер), слабее как конкурсная заявка
- Онбординг/Performance review как переобозначенная воронка — не проработано в глубину, только зафиксирован сам приём
