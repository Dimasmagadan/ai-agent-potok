# Модель данных Потока

## Схема сущностей

```
Company (компания)
  ├── Users (рекрутеры, менеджеры)
  ├── CompanyDepartments (отделы/подразделения)
  ├── Jobs (вакансии)
  │     ├── Stages (этапы воронки, упорядочены)
  │     │     └── stage_type: sourced → screening → phone_interview
  │     │         → interview_hr → interview_client → offer → accepted
  │     └── AJS Joins (связь кандидат ↔ вакансия ↔ этап)
  │           ├── active: true/false (в работе или завершён)
  │           ├── state_id (статус на текущем этапе)
  │           └── declined_at + declination_reason (если отклонён)
  ├── Applicants (кандидаты)
  │     ├── Может быть на нескольких вакансиях одновременно
  │     ├── Documents (резюме, документы)
  │     └── Events (комментарии, звонки, встречи)
  ├── Dictionaries (справочники)
  │     ├── DeclinationReasons (причины отказа)
  │     ├── ApplicantSources (источники кандидатов)
  │     └── Cities, Specializations, ...
  └── Finalists (принятые на работу кандидаты)
```

## Ключевые сущности

### Job (Вакансия)
Позиция, на которую ведётся набор. Имеет воронку из этапов (Stages), статус (активная/архивная), ответственного рекрутера и отдел.

### Applicant (Кандидат)
Человек, рассматриваемый на позицию. Хранит ФИО, контакты, резюме. Один кандидат может быть на нескольких вакансиях одновременно.

### AJS Join (Applicant-Job-Stage)
**Центральная сущность** — связь кандидата с вакансией на конкретном этапе воронки. Через AJS Join происходит всё управление процессом: перемещение по этапам, смена статусов, отклонение.

- `id` (ajs_id) — используется для всех операций перемещения
- `stage_id` → текущий этап воронки
- `active` → в работе (true) или завершён (false)
- `state_id` → статус внутри этапа (зависит от настроек)
- `declined_at` → дата отклонения (если отклонён)

### Stage (Этап воронки)
Этап рекрутингового процесса внутри вакансии. Каждая вакансия имеет свой набор этапов.

**Типовые stage_type (по порядку):**

| stage_type | Описание |
|------------|----------|
| `applied` | Кандидат откликнулся сам |
| `sourced` | Рекрутер добавил кандидата |
| `screening` | Первичный скрининг |
| `phone_interview` | Телефонное интервью |
| `interview_hr` | Собеседование с HR |
| `interview_client` | Собеседование с нанимающим менеджером |
| `offer` | Оффер |
| `accepted` | Принят на работу |
| `declined` | Отклонён (системный, не создаётся вручную) |

### Event (Событие)
Комментарий, звонок, встреча или другая активность, привязанная к кандидату и (опционально) к вакансии.

Типы: `comment`, `call`, `meeting`, `email`, `task`

### User (Пользователь)
Рекрутер или менеджер в компании. Может быть ответственным за вакансию (`executive_recruiter`) или назначенным на конкретного кандидата.

### Document (Документ)
Файл, прикреплённый к кандидату (резюме, паспорт, диплом и т.д.). Загружается через API v2 как `multipart/form-data`.

## Жизненный цикл кандидата

```
1. Создание кандидата (POST /applicants)
   ↓
2. Добавление на вакансию → создаётся AJS Join (POST /ajs_joins)
   ↓
3. Перемещение по воронке (POST /ajs_joins/:id/move_to_next_stage)
   sourced → screening → interview_hr → interview_client → offer → accepted
   ↓
4a. Принят → Финалист (GET /finalists)
4b. Отклонён → decline с причиной (POST /jobs/:job_id/:applicant_id/decline)
```

## Связи между API-версиями

| Операция | API-версия | Эндпоинт |
|----------|-----------|----------|
| Вакансии CRUD | v3 | `/api/v3/jobs` |
| Кандидаты CRUD | v3 | `/api/v3/applicants` |
| Перемещение по воронке | v3 | `/api/v3/ajs_joins/:id/...` |
| Пользователи | v3 | `/api/v3/users` |
| Комментарии и события | v2 | `/api/v2/events` |
| Загрузка документов | v2 | `/api/v2/documents` |
| Справочники | v2 + v3 | `/api/v2/dictionaries`, `/api/v3/dictionaries` |
| Карьерный сайт | open | `/open/...` |
| Вебхуки (push из Потока) | — | настраиваются по запросу, см. [15-webhooks.md](15-webhooks.md) |
