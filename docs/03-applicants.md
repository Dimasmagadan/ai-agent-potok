# Кандидаты (Applicants)

API v3: `/api/v3/applicants`

---

### GET /api/v3/applicants

**Когда использовать:** Получить список кандидатов компании. Поддерживает полнотекстовый поиск через Elasticsearch.

> ⚠️ **Параметр `q` передаётся в формате Rails nested params** (`q[][s]=...&q[][types][]=fios&q[][op]=and`), а НЕ как JSON-строка. JSON-формат вернёт 500. Подробнее — см. Рецепт 2 в [13-recipes.md](13-recipes.md).

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `page` | integer | Нет | Номер страницы (с 1) |
| `per_page` | integer | Нет | Записей на странице (по умолчанию 50, макс 100) |
| `q` | array | Нет | Полнотекстовый поиск (см. ниже) |
| `f` | object | Нет | Точные фильтры: телефон, email, вакансии, теги, город и др. (см. ниже) |

> Максимальная глубина выдачи — 10 000 записей (`page × per_page`). Дальше — сужайте фильтры.

**Поиск (параметр `q`):**

> ⚠️ Параметр `q` передаётся в формате **Rails nested params**, а не как JSON-строка!

```
GET /api/v3/applicants?q[][s]=Иван Иванов&q[][types][]=fios&q[][op]=and&per_page=20
```

Пример на Python (requests):
```python
params = {
    "per_page": 20,
    "q[][s]": "Иван Иванов",
    "q[][types][]": "fios",
    "q[][op]": "and"
}
response = requests.get("/api/v3/applicants", params=params, headers=headers)
```

| Поле | Описание |
|------|----------|
| `q[][s]` | Поисковая строка |
| `q[][types][]` | Где искать: `fios` (ФИО), `phones`, `emails` |
| `q[][op]` | Оператор: `and` (все слова совпадут), `or` (любое) |

**Точный поиск по телефону и email (фильтр `f`):**

Когда контакт известен точно (авторизация в личном кабинете, проверка на дубль перед созданием, матчинг с внешней базой) — используйте фильтр `f` вместо `q`. Это точное совпадение, без нечёткости полнотекстового поиска.

```
GET /api/v3/applicants.json?f[phones][]=79161234567
GET /api/v3/applicants.json?f[emails][]=mail@example.com
```

| Фильтр | Как ищет |
|--------|----------|
| `f[phones][]` | Точное совпадение по любому из телефонов кандидата |
| `f[emails][]` | Точное совпадение по основному **и** дополнительным email |

- **Формат телефона:** цифры с кодом страны, без `+` и разделителей — `79161234567`. Телефоны в Потоке хранятся нормализованными в международном формате, поэтому `+7 (916) 123-45-67` не совпадёт.
- **Батч:** можно передать до **50** значений за запрос (`f[phones][]=...&f[phones][]=...`) — удобно для сверки списков. Больше 50 → 422.
- Пустой `data` — кандидата с таким контактом нет.

Помимо контактов, `f` принимает и другие точные фильтры: `jobs`, `stages`, `stage_types`, `tags`, `sources`, `cities`, `responsible_users`, `created_at`, `born`, `salary`, `citizenship`, `education_level` и др.

**Ответ 200:**
```json
{
  "data": [{
    "id": 12345,
    "first_name": "Иван",
    "last_name": "Иванов",
    "middle_name": "Петрович",
    "email": "ivan@example.com",
    "phones": ["79991234567"],
    "born": "1990-05-15",
    "salary": 100000,
    "city": {"id": "1", "name": "Москва"},
    "title": "Разработчик",
    "tags": ["VIP", "Python"],
    "source_type": "applied",
    "source_name": "HeadHunter",
    "resumes": [{"id": 100, "cv_original": "https://.../resume.pdf"}],
    "states": [{"workflow_name": "personal_data_agreement", "state_id": "accepted"}]
  }],
  "page": 1, "per_page": 20, "pages": 5
}
```

**Ключевые поля:**
- `phones` — массив строк (без форматирования)
- `resumes` — массив резюме с URL файлов
- `source_type` — как попал: `applied` (сам), `sourced` (рекрутер)
- `tags` — теги, назначенные рекрутерами
- `states` — статусы по workflow (согласие на обработку данных и т.д.)

### GET /api/v3/applicants/:id

**Когда использовать:** Получить полную карточку кандидата — ФИО, контакты, резюме, теги, workflow-статусы.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `id` | integer | Да | ID кандидата (path) |

**Ответ:** полный объект кандидата (аналогичен элементу из `data` в GET /applicants, но с полными данными).

**Следующий шаг:** GET /jobs/:job_id/ajs_joins?applicant_id=:id — узнать на каких вакансиях и этапах кандидат

---

### POST /api/v3/applicants

**Когда использовать:** Создать нового кандидата. Можно сразу привязать к вакансии через `job_id`.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `first_name` | string | Да | Имя |
| `last_name` | string | Да | Фамилия |
| `middle_name` | string | Нет | Отчество |
| `phone` | string | Нет | Телефон |
| `email` | string | Нет | Email |
| `job_id` | integer | Нет | ID вакансии (автоматически создаст AJS Join) |
| `resume` | string | Нет | Base64-файл или URL резюме |
| `city` | string | Нет | Город |
| `born` | date | Нет | Дата рождения (YYYY-MM-DD) |
| `salary` | integer | Нет | Зарплатные ожидания |

**Запрос:**
```json
{"first_name": "Иван", "last_name": "Петров", "phone": "+79991234567", "email": "ivan@example.com", "job_id": 12345}
```

**Ошибки:** 422 `email уже существует` — кандидат с таким email уже есть

**Следующий шаг:** Если `job_id` не указан → POST /ajs_joins для добавления на вакансию

---

### PUT /api/v3/applicants/:id

**Когда использовать:** Обновить данные кандидата (контакты, город, зарплату и т.д.).

Параметры — те же, что у POST. Передавайте только поля для обновления.

---

### POST /api/v3/applicants/:id/resume_file

**Когда использовать:** Загрузить файл резюме к кандидату.

**Content-Type:** `multipart/form-data`

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `id` | integer | Да | ID кандидата (path) |
| `file` | file | Да | Файл резюме (PDF, DOC, DOCX) |

---

### POST /api/v3/applicants/:applicant_id/depersonalize

**Когда использовать:** Деперсонализировать кандидата (удалить персональные данные). Необратимая операция — используется для GDPR/закона о персональных данных.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `applicant_id` | integer | Да | ID кандидата (path) |

**Ответ 200:** кандидат с очищенными полями (ФИО, контакты, резюме = null)

---

### GET /api/v3/applicants/:applicant_id/offers

**Когда использовать:** Получить список офферов кандидата.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `applicant_id` | integer | Да | ID кандидата (path) |

## Поиск через API v2

### GET /api/v2/applicants

**Когда использовать:** Простой поиск кандидатов по текстовому запросу (ФИО, телефон, email). Проще чем v3, но менее гибкий.

> ⚠️ **Этот эндпоинт может быть нестабильным** (иногда возвращает 500). Если не работает — используйте v3 поиск (GET /api/v3/applicants с параметром `q`). По умолчанию scope = `active` — архивные кандидаты не вернутся без `by_scope=all`.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `query` | string | Нет | Текст поиска |
| `by_scope` | string | Нет | `active`, `archive`, `all` |
| `by_job_id` | integer | Нет | Фильтр по вакансии |
| `by_created_at` | array | Нет | Период создания (2 даты) |
| `page` | integer | Нет | Страница |
| `per_page` | integer | Нет | Записей на странице |
