# AJS Joins — перемещение по воронке

API v3: `/api/v3/ajs_joins`

AJS Join (Applicant-Job-Stage) — **центральная сущность**, связывающая кандидата с вакансией на конкретном этапе воронки. Все операции по перемещению кандидатов проходят через AJS Join.

---

### POST /api/v3/ajs_joins

**Когда использовать:** Добавить существующего кандидата на вакансию. Вызывайте после создания кандидата (POST /applicants), если он ещё не привязан к вакансии.

**Связь:** Создаёт AJS Join — связь Applicant ↔ Job на начальном этапе воронки.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `job_id` | integer | Да | ID вакансии |
| `applicant_id` | integer | Да | ID кандидата |
| `stage_type` | string | Да | `sourced` (рекрутер добавил) или `applied` (кандидат откликнулся) |

**Запрос:** `{"job_id": 12345, "applicant_id": 67890, "stage_type": "sourced"}`

**Ответ 200:**
```json
{
  "id": 111222,
  "job": {"id": 12345, "name": "Frontend Developer"},
  "applicant": {"id": 67890, "name": "Иванов Иван"},
  "stage": {"id": 100, "name": "Добавлен", "serial": 1, "stage_type": "sourced"}
}
```

**Ошибки:**
- 422 `ajs_join exists` — кандидат уже на этой вакансии
- 422 `job not_found` — вакансия не найдена
- 422 `applicant is_not_active` — кандидат деактивирован

**Следующий шаг:** POST /ajs_joins/:id/move_to_next_stage

---

### POST /api/v3/ajs_joins/:id/move_to_next_stage

**Когда использовать:** Переместить кандидата на следующий этап воронки. Самая частая операция — двигает на ближайший этап с `serial` больше текущего.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `id` | integer | Да | ID AJS Join (path) |

**Запрос:** тело не требуется

**Ответ 200:**
```json
{"id": 111222, "stage_id": 101, "applicant_id": 67890, "job_id": 12345, "stage_type": "screening", "state_id": null}
```

**Ошибки:** 404 — кандидат уже на последнем этапе

---

### POST /api/v3/ajs_joins/:id/change_stage

**Когда использовать:** Переместить кандидата на конкретный этап по ID этапа. Используйте, когда нужно перепрыгнуть несколько этапов или вернуть назад.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `id` | integer | Да | ID AJS Join (path) |
| `stage_id` | integer | Да | ID целевого этапа |

**Запрос:** `{"stage_id": 105}`

**Ошибки:** 404 — этап не найден на этой вакансии; 422 — переход запрещён

**Как узнать ID этапа:** GET /jobs/:id → поле `stages` содержит все этапы с их ID

---

### POST /api/v3/ajs_joins/:id/move_to_stage_type

**Когда использовать:** Переместить кандидата на первый этап указанного типа. Удобно, когда вы знаете тип (например, `offer`), но не знаете конкретный ID этапа.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `id` | integer | Да | ID AJS Join (path) |
| `to_stage_type` | string | Да | Тип целевого этапа |

**Допустимые типы:** `sourced`, `applied`, `screening`, `interview_hr`, `interview_client`, `offer`, `accepted`

**Запрос:** `{"to_stage_type": "offer"}`

---

### POST /api/v3/ajs_joins/:id/change_state

**Когда использовать:** Сменить статус кандидата **внутри текущего этапа** (например, «интервью назначено», «ожидает решения»). Статусы настраиваются индивидуально для каждой компании.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `id` | integer | Да | ID AJS Join (path) |
| `state_id` | string | Да | ID статуса (из настроек компании) |

**Запрос:** `{"state_id": "interview_scheduled"}`

**Ответ 200:**
```json
{"id": 111222, "stage_id": 102, "stage_type": "screening", "state_id": "interview_scheduled"}
```

**Ошибки:** 404 — state_id не найден в настройках компании

---

### PATCH /api/v3/ajs_joins/:id

**Когда использовать:** Обновить данные AJS Join — планируемую дату выхода, привязку к заявке, динамические поля.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `id` | integer | Да | ID AJS Join (path) |
| `planned_employment_date` | date | Нет | Планируемая дата выхода |
| `demand_id` | integer | Нет | ID заявки |
| `assessed_at` | datetime | Нет | Дата оценки |

---

### POST /api/v3/jobs/:job_id/:applicant_id/decline.json

**Когда использовать:** Отклонить кандидата на вакансии с указанием причины.

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `job_id` | integer | Да | ID вакансии (path) |
| `applicant_id` | integer | Да | ID кандидата (path) |
| `declination_reason_id` | integer | Да | ID причины отказа |

**Как узнать причины:** GET /api/v2/declination_reasons

---

## Модель данных AJS Join

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer | ID (используется во всех операциях перемещения) |
| `job_id` | integer | ID вакансии |
| `applicant_id` | integer | ID кандидата |
| `stage_id` | integer | ID текущего этапа |
| `stage_type` | string | Тип текущего этапа |
| `state_id` | string | Статус на этапе (null если не установлен) |
| `active` | boolean | В работе (true) или завершён (false) |
| `responsible_user_id` | integer | Ответственный рекрутер |
| `planned_employment_date` | date | Планируемая дата выхода |
| `declined_at` | datetime | Дата отклонения (если отклонён) |
| `stage_changed_at` | datetime | Дата последней смены этапа |

## Ограничения

- Один кандидат может быть на одной вакансии только один раз
- При создании допустимы только `sourced` и `applied`
- Смена этапа возможна только на этапы той же вакансии
