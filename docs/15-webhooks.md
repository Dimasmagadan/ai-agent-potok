# Вебхуки (Webhooks)

Поток умеет отправлять вебхуки — HTTP-запросы на ваш URL при событиях в системе. Это альтернатива поллингу через `events_stream`: данные приходят сами в момент события.

> ⚠️ **Самостоятельной настройки вебхуков пока нет.** Вебхуки настраивает команда Потока по запросу — напишите нам, какой URL, какие события и какие поля нужны, и мы настроим. Обычно это быстро.

---

## На что можно подписаться

Вебхуки вешаются на основные сущности и их события:

| Сущность | События |
|----------|---------|
| **Кандидат** (applicant) | создание, обновление, смена этапа воронки (`applicant/stage_changed`), деперсонализация |
| **Вакансия** (job) | создание, обновление, смена статуса (`job/state_changed`), изменение даты закрытия |
| **Кандидат на вакансии** (ajs_join) | создание, обновление, отклонение, возврат в работу, смена статуса на этапе, назначение ответственного |
| **Событие** (event) | создание комментария/звонка/встречи |
| **Workflow** | завершение перехода в кастомном workflow (см. [16-integration.md](16-integration.md)) |

Типичные подписки для интеграций: создание кандидата, создание вакансии, движение кандидата по воронке (перевод на конкретный тип этапа — например, только на `offer`).

Вебхук можно ограничить условием (matcher) — например, слать только при переводе на определённый этап или только по определённым вакансиям.

## Формат запроса

Поток отправляет POST (метод настраиваемый) с JSON:

```json
{
  "event": "ajs_join/applicant_state_changed",
  "data": {
    "id": 51562161,
    "applicant_id": 42213690,
    "job_id": 1083910
  }
}
```

- `event` — идентификатор вида `<сущность>/<имя вебхука>`; имя задаётся при настройке (обычно по смыслу события: `applicant/created`, `job/state_changed`)
- `data` — поля сущности. **Состав настраивается под вас**: можно только ID (а детали вы дозапросите через API), а можно сразу полные данные с вложенными связями:

```json
{
  "event": "ajs_join/applicant_state_changed",
  "data": {
    "id": 51562161,
    "active": true,
    "applicant": {"id": 42213690, "name": "Иван Иванов"},
    "stage": {"id": 789, "name": "Оффер"},
    "job": {"id": 1083910, "name": "Backend Developer"}
  }
}
```

Данные в `data` — актуальное состояние сущности на момент отправки (не снапшот на момент события).

## Авторизация вебхука

На выбор при настройке:

| Способ | Как выглядит |
|--------|--------------|
| Токен | Заголовок `Authorization: <ваш токен>` (значение подставляется как есть) |
| Basic Auth | Логин + пароль |
| Без авторизации | — |

Заголовки запроса: `Content-Type: application/json`, `Accept: application/json`.

---

## Доставка и ретраи

- Успех = ответ **2xx**. Отвечайте `200` сразу, обработку делайте асинхронно.
- При ошибке (не-2xx, таймаут, сетевые ошибки) Поток повторяет отправку до **14 раз** с нарастающей задержкой (от ~1 минуты до часов между последними попытками; полный цикл растягивается на несколько дней).
- Каждая попытка логируется на стороне Потока — при разборе проблем можно поднять историю доставки.

**Идемпотентность:** из-за ретраев одно событие может прийти дважды — дедуплицируйте по `data.id` + `event`.

## Вебхук vs events_stream

| | Вебхуки | events_stream |
|---|---------|--------------|
| Модель | Push — Поток шлёт сам | Pull — вы опрашиваете |
| Задержка | Секунды | Зависит от частоты опроса |
| Настройка | Через команду Потока | Работает сразу, через API |
| Что покрывает | События сущностей | Лента событий (комментарии, смены этапов...) |

Практичный паттерн: вебхук как сигнал (получили `id`) → дозапрос деталей через API → при недоверии к доставке раз в час сверка через `events_stream` (Рецепт 8 в [13-recipes.md](13-recipes.md)).
