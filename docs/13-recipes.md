# Рецепты — пошаговые сценарии

Готовые цепочки API-вызовов для типичных задач рекрутинга.

---

## Рецепт 1: Найти вакансию по названию

**Цель:** Найти вакансию, зная только её название (или часть названия).

### Способ A: Полнотекстовый поиск (рекомендуемый)

```
GET /api/v3/cursor_paginated/jobs?q=Руководитель 1С&by_scope=all
```
→ Возвращает вакансии, подходящие под запрос. Поиск через Elasticsearch.

> `by_scope=active` (по умолчанию) — только открытые/приостановленные. Если вакансия закрыта или отменена — используйте `by_scope=all`.

### Способ B: Перебор + клиентская фильтрация (фоллбэк)

Если cursor_paginated не находит (или нужен точный контроль над фильтрацией):

**Шаг 1.** Загрузить все вакансии
```
GET /api/v3/jobs?by_scope=all&per_page=100&page=1
```
→ В ответе `pages` — общее количество страниц. Повторить для каждой страницы.

**Шаг 2.** Отфильтровать по названию на стороне клиента
```python
search = "руководитель 1с"
matches = [j for j in all_jobs if search.lower() in j["name"].lower()]
```

**Подводные камни:**
- Название может не совпадать точно: "Руководитель 1С" vs "Руководитель отдела 1С" vs "1С-разработчик"
- Используйте нечёткий поиск (подстрока), а не точное совпадение
- При > 500 вакансиях перебор неэффективен — используйте cursor_paginated

## Рецепт 2: Найти кандидата по ФИО

**Цель:** Найти кандидата по имени/фамилии.

Есть два способа — через v3 (Elasticsearch, надёжнее) и v2 (простой, но может не работать).

### Способ A: API v3 (рекомендуемый)

> ⚠️ Параметр `q` передаётся в формате **Rails nested params**, а не JSON!

```
GET /api/v3/applicants?q[][s]=Фещенко&q[][types][]=fios&q[][op]=and
```

Пример на Python:
```python
params = {
    "q[][s]": "Фещенко",
    "q[][types][]": "fios",
    "q[][op]": "and"
}
response = requests.get(url + "/api/v3/applicants", params=params, headers=headers)
```

| Параметр | Описание |
|----------|----------|
| `q[][s]` | Строка поиска — ФИО целиком или часть |
| `q[][types][]` | Где искать: `fios` (по имени), `phones`, `emails` |
| `q[][op]` | `and` — все слова должны совпасть, `or` — любое |

### Способ B: API v2 (простой)
```
GET /api/v2/applicants?query=Фещенко
```

> Если известен точный телефон или email — не ищите текстом, используйте точный фильтр `f` (Рецепт 11).

> ⚠️ v2 поиск может быть нестабильным (иногда возвращает 500). Если v2 не работает — используйте v3.

### Если поиск не находит

Проверьте:
1. **Scope** — по умолчанию `active`. Кандидат в архиве? → добавьте `by_scope=all` (v2) или уберите фильтр scope
2. **Написание ФИО** — "Фещенко" vs "Фещенко" (ё/е), пробелы, регистр. Попробуйте искать только по фамилии
3. **Кандидат на вакансии?** — если знаете вакансию, можно получить всех кандидатов через `GET /api/v3/jobs/{job_id}/ajs_joins` и найти среди них
4. **Кандидат недавно добавлен** — индексация Elasticsearch может занять до нескольких минут

### Фоллбэк: перебор кандидатов вакансии
Если ни v3, ни v2 не находят, а вакансия известна:
```
GET /api/v3/jobs/{job_id}/ajs_joins?page_size=100
```
→ Для каждого `applicant_id` из ответа → `GET /api/v3/applicants/{applicant_id}` → сравнить ФИО на стороне клиента.

## Рецепт 3: Найти кандидатов на конкретной вакансии

**Цель:** Получить всех кандидатов, прикреплённых к вакансии (по ID вакансии).

> ⚠️ `GET /api/v3/applicants?by_job_id=X` **не фильтрует по вакансии** — параметр игнорируется, возвращаются все кандидаты компании. Для получения кандидатов конкретной вакансии используйте **ajs_joins**.

**Шаг 1.** Получить связки кандидат-вакансия
```
GET /api/v3/jobs/{job_id}/ajs_joins?page_size=100
```
→ Возвращает `objects` — массив AJS Joins с `applicant_id` каждого кандидата.

**Шаг 2.** Если нужна полная карточка кандидата
```
GET /api/v3/applicants/{applicant_id}
```
→ Повторить для каждого `applicant_id` из шага 1.

**Шаг 3.** Если кандидатов много — использовать курсорную пагинацию
```
GET /api/v3/jobs/{job_id}/ajs_joins?page_size=100&page_cursor={page_next_cursor}
```
→ Повторять пока `has_next_page = true`.

## Рецепт 4: Создать вакансию и добавить кандидата

**Цель:** Создать вакансию, создать кандидата, привязать к вакансии.

**Шаг 1.** Создать вакансию
```
POST /api/v3/jobs
{"name": "Python Developer", "city": "1", "salary_from": 200000, "schedule_type": "remote"}
```
→ Запомнить `id` из ответа (например, `job_id = 12345`)

**Шаг 2.** Создать кандидата с привязкой к вакансии
```
POST /api/v3/applicants
{"first_name": "Иван", "last_name": "Петров", "phone": "+79991234567", "email": "ivan@example.com", "job_id": 12345}
```
→ Кандидат создан и автоматически добавлен на вакансию (AJS Join создаётся автоматически)

**Готово.** Кандидат появится на первом этапе воронки вакансии.

## Рецепт 5: Переместить кандидата по воронке

**Цель:** Провести кандидата через этапы: sourced → screening → interview → offer → accepted.

**Шаг 1.** Найти AJS Join кандидата на вакансии
```
GET /api/v3/jobs/12345/ajs_joins?applicant_id=67890
```
→ Из ответа берём `objects[0].id` (например, `ajs_id = 111222`)

**Шаг 2.** Переместить на следующий этап
```
POST /api/v3/ajs_joins/111222/move_to_next_stage
```
→ Кандидат перемещён на screening

**Шаг 3.** Перепрыгнуть на конкретный тип этапа (например, сразу на offer)
```
POST /api/v3/ajs_joins/111222/move_to_stage_type
{"to_stage_type": "offer"}
```

**Альтернатива:** Если нужен конкретный этап по ID (из `stages` вакансии):
```
POST /api/v3/ajs_joins/111222/change_stage
{"stage_id": 105}
```

## Рецепт 6: Найти застрявших кандидатов

**Цель:** Найти кандидатов, которые находятся на одном этапе дольше N дней.

**Шаг 1.** Получить всех активных кандидатов на вакансии
```
GET /api/v3/jobs/12345/ajs_joins?page_size=100
```

**Шаг 2.** Для каждого кандидата в `objects` — вычислить разницу между текущей датой и `datetime_of_create` (или дата последнего события через GET /api/v2/events?applicant_id=...). Если разница > порога — кандидат «застрял».

**Пример логики (на стороне агента):**
```
сегодня = 2024-03-20
для каждого ajs_join:
  если (сегодня - ajs_join.datetime_of_create) > 7 дней:
    добавить в список застрявших
```

## Рецепт 7: Анализ причин отказов

**Цель:** Получить статистику причин отказов по вакансии.

**Шаг 1.** Получить причины отказа
```
GET /api/v2/declination_reasons
```
→ Массив: `[{"id": 1, "name": "Не подходит по опыту", "initiator": "from_recruiter"}, ...]`

> Ответ — массив напрямую (без обёртки `{data: [...]}`). Поле `initiator`: `from_recruiter`, `from_applicant`, `from_director`.

**Шаг 2.** Получить кандидатов вакансии через AJS Joins
```
GET /api/v3/jobs/12345/ajs_joins?page_size=100
```
→ Среди `objects` отфильтровать тех, у кого `active = false` (отклонённые).

> ⚠️ `GET /api/v3/applicants?by_job_id=X` **не фильтрует** по вакансии — параметр игнорируется. Используйте ajs_joins.

**Шаг 3.** Для каждого отклонённого — получить причину из `declination_reason_id` и подставить название из шага 1.

## Рецепт 8: Синхронизация через events_stream

**Цель:** Периодически забирать все новые события (для интеграции с внешней системой).

**Алгоритм:**

```
cursor = null  # при первом запуске

цикл:
  ответ = GET /api/v2/events_stream?page_size=100&page_cursor={cursor}

  для каждого события в ответ.objects:
    обработать событие

  если ответ.has_next_page:
    cursor = ответ.page_next_cursor
  иначе:
    сохранить cursor для следующего запуска
    завершить
```

**Важно:** Сохраняйте `page_cursor` между запусками, чтобы не загружать уже обработанные события.

**Для аналитики:** в потоке идут и системные события — `Event::StageChanged` (движение по воронке), `Event::StateChanged` (смена статусов). Из них собирается вся динамика воронки: конверсия этапов, скорость прохождения, активность рекрутеров — без выгрузки всех кандидатов.

**Push вместо pull:** если нужна реакция в реальном времени — есть вебхуки, см. [15-webhooks.md](15-webhooks.md).

## Рецепт 9: Карьерный сайт — отклик на вакансию

**Цель:** Показать вакансии на карьерном сайте и принять отклик.

**Шаг 1.** Получить список вакансий (публичный, без авторизации)
```
GET https://acme.potok.io/open/jobs
```

**Шаг 2.** Показать детали вакансии
```
GET https://acme.potok.io/open/jobs/12345
```

**Шаг 3.** Отправить отклик
```
POST https://acme.potok.io/open/jobs/12345/apply
Content-Type: multipart/form-data

first_name=Иван&last_name=Петров&phone=+79991234567&email=ivan@example.com&resume=<файл>
```

→ Кандидат создаётся и добавляется на вакансию со stage_type `applied`.

## Рецепт 10: Полный цикл — от заявки до найма

**Цель:** Полный рекрутинговый процесс через API.

**Шаг 1.** Создать вакансию
```
POST /api/v3/jobs
{"name": "Backend Developer", "salary_from": 250000, "salary_to": 400000, "schedule_type": "remote"}
```
→ `job_id = 100`

**Шаг 2.** Назначить рекрутера
```
POST /api/v3/jobs/100/assign_executive_recruiter
{"email": "recruiter@company.com"}
```

**Шаг 3.** Добавить кандидата
```
POST /api/v3/applicants
{"first_name": "Мария", "last_name": "Сидорова", "email": "maria@example.com", "job_id": 100}
```
→ `applicant_id = 200`, автоматически создан AJS Join

**Шаг 4.** Найти AJS Join
```
GET /api/v3/jobs/100/ajs_joins?applicant_id=200
```
→ `ajs_id = 300`

**Шаг 5.** Добавить комментарий после скрининга
```
POST /api/v2/events
{"applicant_id": 200, "body": "Хороший опыт в Python и FastAPI", "type": "comment", "job_id": 100}
```

**Шаг 6.** Переместить на интервью
```
POST /api/v3/ajs_joins/300/move_to_stage_type
{"to_stage_type": "interview_hr"}
```

**Шаг 7.** Запланировать собеседование
```
POST /api/v3/calendar/schedules
{"schedule": {"from": "2024-02-01T14:00:00+03:00", "to": "2024-02-01T15:00:00+03:00", "applicant_id": 200, "job_id": 100, "author_id": 50, "body": "Техническое интервью"}}
```

**Шаг 8.** Принять кандидата (переместить на accepted)
```
POST /api/v3/ajs_joins/300/move_to_stage_type
{"to_stage_type": "accepted"}
```

→ Кандидат появится в списке финалистов (GET /api/v3/finalists?job_id=100).

## Рецепт 11: Найти кандидата по телефону или email

**Цель:** Найти кандидата по точному контакту — авторизация в личном кабинете, проверка на дубль перед созданием, матчинг с внешней базой.

```
GET /api/v3/applicants.json?f[phones][]=79161234567
GET /api/v3/applicants.json?f[emails][]=mail@example.com
```

→ Точное совпадение (не полнотекстовый поиск): телефон — по любому из номеров кандидата, email — по основному и дополнительным адресам.

**Формат телефона:** цифры с кодом страны, без `+` и разделителей: `79161234567`. Телефоны хранятся нормализованными — `+7 (916) 123-45-67` не совпадёт.

**Батч-сверка:** до 50 значений за запрос:
```
GET /api/v3/applicants.json?f[phones][]=79161234567&f[phones][]=79031234567
```

**Типовые применения:**
- **Личный кабинет кандидата** — авторизация по номеру телефона: код по SMS → `f[phones][]` → карточка и статусы кандидата
- **Дедупликация** — перед POST /applicants проверить, что кандидата с таким контактом ещё нет
- **Чат-бот** — соискатель пишет в WhatsApp/Telegram → по номеру находим кандидата и его вакансии

**Следующий шаг:** `GET /api/v3/applicants/{id}` — полная карточка; `GET /api/v3/jobs/{job_id}/ajs_joins?applicant_id={id}` — на каких этапах.

## Рецепт 12: Прикрепить документ к кандидату

**Цель:** Положить файл (отчёт, сертификат, скан) в карточку кандидата.

**Неочевидный момент:** документ сначала **создаётся** как отдельная сущность, потом **прикрепляется** — либо сразу к кандидату, либо через комментарий в ленту кандидата на вакансии.

### Способ A: Напрямую к кандидату

```
POST /api/v2/documents
Content-Type: multipart/form-data

attach=<файл>&name=Отчёт о проверке&target=applicant&target_id=42213690&category=security_check_result
```

→ Документ появится в разделе документов кандидата.

### Способ B: В ленту кандидата на вакансии (через комментарий)

Если документ относится к конкретной вакансии (результат проверки, тестовое задание) — прикрепите его комментарием, чтобы он был виден в ленте событий:

**Шаг 1.** Создать документ
```
POST /api/v3/documents.json
Content-Type: multipart/form-data

attach=<файл>&name=Отчёт&category=security_check_result
```
→ `{"document": {"id": 4410048, ...}}`

**Шаг 2.** Прикрепить комментарием
```
POST /api/v2/events
{"applicant_id": 42213690, "job_id": 1083910, "body": "Отчёт о проверке", "type": "Event::Comment", "attach_document_ids": [4410048]}
```

**Ограничения файлов:** до 10 МБ; запрещены html, css, js, exe. Категории — GET /api/v2/documents/available_categories.
