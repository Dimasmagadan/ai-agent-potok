# Брейншторм идей для конкурса — сессия GLM, 2026-08-18

Статус: **режим широкой генерации идей, ничего не выбрано финально**.

Этот файл продолжает [`BRAINSTORM.md`](BRAINSTORM.md): не заменяет предыдущую сессию, а добавляет новые идеи после чтения документации по штатному расписанию, вебхукам и внешним интеграциям.

## Установки Дмитрия для этой сессии

- Пока не учитывать доступное время на разработку.
- Интересны все возможные результаты участия, приоритет между ними пока не нужен.
- Генерировать как можно больше идей, не ограничиваться одной заявкой.
- Разговор со знакомым рекрутером возможен на этой неделе.

## Новый контекст из документации API

В предыдущем обсуждении не были полноценно учтены следующие возможности.

### Штатное расписание и заявки на подбор

Модуль `Staffing & Demands` предоставляет:

- заявки на подбор с количеством сотрудников, сроками, приоритетом и ответственным рекрутером;
- организационную структуру и штатные позиции;
- спринты кадрового планирования;
- связь заявки с вакансией и фактически нанятыми кандидатами.

Это позволяет строить не только сервисы для работы с кандидатами, но и агентов для планирования найма, прогнозирования сроков и контроля исполнения заявок.

### Вебхуки

«Поток» может отправлять внешней системе события о создании и изменении вакансий, кандидатов, этапов воронки, комментариев и workflow. Вебхуки настраиваются командой «Потока» по запросу.

Практический паттерн:

1. Вебхук сообщает об изменении.
2. Агент запрашивает детали через API.
3. Агент выполняет анализ или внешнюю операцию.
4. Результат возвращается в карточку кандидата комментарием, документом или обновлением полей.

### Каноническая внешняя интеграция

Документ `docs/16-integration.md` описывает продуктивный сценарий:

`кандидат дошёл до этапа → вебхук → внешняя система → workflow-статус → результат в карточку`.

Эта схема подходит не только для проверки службы безопасности, но и для скоринга, тестирования, расшифровки интервью, проверки документов, генерации отчётов и любых AI-сервисов обогащения данных.

### Function calling

В `docs/tools.json` описаны 39 готовых инструментов с JSON Schema. Их можно использовать как основу для LLM-скилла или агента, который вызывает API «Потока» естественным языком.

### Как повысить воспроизводимость Interview Intelligence

Конкурсной частью сделать универсальный мост `любой транскрипт → карточка кандидата в Потоке`. Локальную транскрипцию через `whisper.cpp` и проект Meet оставить опциональным источником. Тогда проверяющему не нужен Mac и локальная ASR-инфраструктура: можно передать готовый текст, получить структурированное резюме интервью и записать результат в «Поток».

### Почему Vacancy SEO/content agent закрывает личную проблему

У Дмитрия уже есть технический опыт захвата SEO-домена, но не хватает публичного доказательного кейса. Конкурсный open-source проект может стать таким артефактом.

Архитектура `аудит → варианты улучшения → доставка результата в продукт` также переносится на Content Ops и SMM-пайплайн: входной бриф превращается в несколько вариантов контента и структурированный результат.

## Каталог идей

### A. Мониторинг и алерты — паттерн «Нюхослава»

Архитектура: поллер или вебхук → расчёт риска → Telegram-алерт → inline-действия → повторная проверка.

#### 1. Funnel SLA Watchdog

Находит кандидатов, которые находятся на одном этапе дольше заданного срока, и отправляет ответственному рекрутеру алерт.

API: `ajs_joins`, `events_stream`, пользователи, смена этапа.

Статус: идея была в первой сессии.

#### 2. Vacancy Health Monitor

Ищет вакансии без новых откликов, событий или движения кандидатов в течение N дней. Отличает реально проблемные вакансии от временно приостановленных.

API: Jobs, AJS Joins, Events.

#### 3. Demand-vs-Reality Tracker

Сравнивает заявку бизнеса «нанять N человек к дате» с фактической воронкой и числом финалистов. Предупреждает, если текущей скорости недостаточно для выполнения плана.

API: `demands`, `sprints`, `staffing_items`, Jobs, AJS Joins, Finalists.

Особенность: использует модуль кадрового планирования, который может быть менее очевиден другим участникам.

#### 4. Declination Analyzer

Собирает причины отказов кандидатов и рекрутеров, группирует их и показывает, где компания теряет людей: зарплата, долгий процесс, требования, конкретный этап или интервьюер.

API: причины отказов, AJS Joins, Events.

#### 5. Recruiter Workload Balancer

Оценивает активную нагрузку рекрутеров: количество вакансий, кандидатов, просроченных действий и интервью. Предлагает перераспределение.

API: Users, Jobs, AJS Joins, Calendar, Events.

#### 6. Funnel Benchmarker

Строит конверсии и скорость по этапам для вакансий, подразделений и рекрутеров. Отправляет еженедельный дайджест с аномалиями и худшими участками воронки.

API: `events_stream`, Jobs, AJS Joins, Business Units.

### B. Контент и карьерный сайт

#### 7. Vacancy SEO/Content Agent

Проверяет текст вакансии на ясность, структуру, поисковую видимость и конверсионные проблемы. Предлагает новую версию и возвращает рекомендации в «Поток».

API: Jobs, Career API, Events.

Связь с личными задачами: публичный кейс под SEO и Content Ops.

#### 8. Job Multiposter

Берёт карточку вакансии и создаёт варианты текста под разные каналы: карьерный сайт, hh.ru, Telegram, LinkedIn и короткое сообщение для личного контакта.

API: Jobs, Career API, Events; внешние API площадок при наличии.

#### 9. Career Site SEO/GEO Auditor

Анализирует публичный карьерный сайт без доступа к закрытым данным: структуру вакансий, метаданные, Schema.org, индексируемость, качество текстов и доступность для AI-краулеров и генеративного поиска.

API: открытый Career API без токена.

Связь с личными задачами: отдельный продуктовый оффер «аудит карьерного сайта работодателя» и демонстрация SEO/GEO-компетенции.

#### 10. Candidate Nurture Writer

Генерирует персонализированные сообщения кандидатам в зависимости от вакансии, этапа и времени ожидания: напоминание, запрос данных, подготовка к интервью, уведомление о задержке.

API: Applicants, Jobs, AJS Joins, Events.

#### 11. Offer and Welcome Document Generator

Создаёт оффер, список условий, welcome-письмо или пакет инструкций на основе карточки кандидата и вакансии. Прикрепляет результат к кандидату.

API: Applicants, Jobs, Documents, Events.

### C. Интервью — развитие проекта Meet

#### 12. Interview Intelligence

Принимает транскрипт интервью, формирует краткое содержание, компетенции, сильные стороны, риски, вопросы без ответа и цитаты. Пишет результат в карточку кандидата и прикрепляет полный отчёт.

API: Events, Documents, Applicants, Jobs.

Статус: идея была в первой сессии; универсальный текстовый вход повышает воспроизводимость.

#### 13. Interview Dossier Coach

До встречи собирает резюме, требования вакансии, предыдущие комментарии и историю этапов. Создаёт персональный список вопросов интервьюеру и список фактов, которые нужно проверить.

API: Applicants, Jobs, Events, Calendar.

#### 14. Interview Feedback Quality Checker

После встречи проверяет, появился ли содержательный и структурированный фидбек. Если комментарий слишком короткий или отсутствует, напоминает интервьюеру и предлагает шаблон.

API: Calendar, Events, Users.

### D. Обогащение кандидата внешней системой

#### 15. Resume Enrichment Agent

Извлекает из резюме структурированные навыки, опыт, языки, должности и отрасли. Обновляет доступные поля карточки и оставляет протокол извлечения.

API: Applicants, Documents, workflow, Events.

#### 16. Screening Matcher

Сравнивает кандидата с требованиями конкретной вакансии, объясняет совпадения и пробелы, предлагает вопросы для скрининга. Решение остаётся за человеком.

API: Applicants, Jobs, Documents, Events.

Отличие от обычного resume checker: сервис работает для рекрутера и оценивает соответствие конкретной вакансии, а не «качество резюме вообще».

#### 17. Duplicate Detector

Проверяет кандидатов по телефонам и email, находит возможные дубли и формирует отчёт для безопасного объединения или очистки базы.

API: точный поиск Applicants по телефонам и email.

#### 18. Reference or Security Check Runner

Запускается при попадании кандидата на специальный этап, получает анкету и документы, выполняет внешнюю проверку, показывает workflow-статус и возвращает отчёт.

API: Webhooks, Applicants, Security Forms, Workflows, Documents, Events.

### E. Использование AJS Join не только для найма

#### 19. Onboarding 30-60-90

После найма сотрудник автоматически попадает в программу адаптации. Этапы отражают чекпоинты, агент напоминает сотруднику и наставнику, собирает обратную связь и готовит итоговый отчёт.

Модель: Job = программа адаптации; Applicant = новый сотрудник; Stage = шаг адаптации.

#### 20. Performance Review Cycle

Проводит сотрудника через самооценку, оценку руководителя, калибровку и итоговый фидбек.

Модель: Job = цикл оценки; Applicant = сотрудник; Stage = этап оценки.

#### 21. Internal Mobility Board

Использует ту же инфраструктуру для внутренних вакансий, кадрового резерва и развития сотрудников. Агент объясняет, какие навыки нужно закрыть для перехода.

API: Jobs, Applicants, AJS Joins, Users, Events.

### F. Мета-аналитика HR-операций

#### 22. Recruiter Activity Audit

Применяет к `events_stream` метод Дмитрия из Bitrix-анализа: классификация операций, поиск повторяющихся процессов, кластеризация и рейтинг возможностей автоматизации.

Результат: отчёт «что рекрутеры делают руками, где образуются задержки и какие три автоматизации окупятся первыми».

Связь с личными задачами: перенос уже реализованного task-tracker audit в HR-домен; сильный доказательный кейс AI Orchestrator.

#### 23. Employer Brand Monitoring

Собирает публичные отзывы и упоминания компании как работодателя, классифицирует темы и тональность, связывает изменения с вакансиями и периодами активного найма.

API «Потока» используется для контекста вакансий и периодов найма; внешние источники дают упоминания.

Связь с личными задачами: применение идеи Brand Monitoring из сервисного скоркарда.

### G. Боты и conversational UI

#### 24. Candidate Status Bot

Кандидат пишет в Telegram или WhatsApp, подтверждает телефон и получает понятный статус своих откликов, дату интервью и следующий шаг.

API: точный поиск по телефону, Applicants, Jobs, AJS Joins, Calendar.

#### 25. Recruiter Telegram Copilot

Рекрутер спрашивает: «Кто завис?», «Какие интервью сегодня?», «Где нет фидбека?». Бот показывает карточки и даёт inline-кнопки для безопасных действий, например перемещения на этап или добавления комментария.

API: готовые function-calling tools из `docs/tools.json`, Jobs, Applicants, AJS Joins, Calendar, Events.

Связь с существующим проектом: переиспользование Telegram UI и recovery-паттерна «Нюхослава».

## One-pager для разговора с рекрутером

### Что умеет API «Потока» простым языком

Через API программа может:

- читать и создавать вакансии, менять их статусы;
- искать кандидатов по имени, телефону или email и читать их карточки;
- создавать кандидатов и добавлять их на вакансии;
- видеть, на каком этапе находится кандидат, и двигать его по воронке;
- читать историю действий и писать комментарии в карточку;
- прикреплять резюме, отчёты и другие документы;
- работать с календарём интервью и напоминаниями;
- видеть причины отказов;
- получать штатное расписание и заявки на подбор, если модуль подключён;
- получать события почти в реальном времени через вебхуки;
- показывать вакансии и принимать отклики через открытое API карьерного сайта;
- подключать внешние проверки или AI-сервисы и возвращать результат прямо в карточку кандидата.

### Вопросы рекрутеру

1. Какие повторяющиеся действия отнимают у тебя больше всего времени каждый день или каждую неделю?
2. Как ты сейчас замечаешь, что кандидат слишком долго находится на одном этапе?
3. Что приходится делать вручную после каждого интервью?
4. Бывают ли дубли кандидатов и насколько трудно их находить?
5. Кто пишет тексты вакансий и понимаете ли вы, какие тексты дают больше качественных откликов?
6. Какие данные приходится копировать между «Потоком», таблицами, мессенджерами и другими системами?
7. Какие отчёты руководство просит регулярно и сколько времени занимает их подготовка?
8. Какая информация чаще всего теряется при передаче кандидата другому рекрутеру или нанимающему менеджеру?
9. Что бы ты первым отдал роботу, если бы он работал надёжно и оставлял решение человеку?

## Вопросы Дмитрия, переданные в эту сессию

1. «давай подумаем, как этот проект может решать мои боли/проблемы?»
2. «сделаем так: посмотри идеи, которые есть у нас; посмотри, какие проблемы есть у меня; давай попробуем применить это к конкурсу и попробуем закрыть какую-то из моих идей/проблем с помощью открытого API»
3. «По поводу доказательного кейса Skill Combo Offer. Получается, используя API потока, мы можем брать и делать сервис, который будет проверять качество резюме. Я правильно понял?»
4. «отложим идеи, что еще можно? попробуй такой подход: берём что-то из реализованных проектов (нюхослав, meet, intercom, holotec и т.д.), смотрим, как можем туда внедрить их API, смотрим, что получится на выходе»
5. «у меня есть знакомый рекрутер, могу прийти с вопросами — напиши коротко, что умеет API «Потока», чтоб я мог спросить у рекрутера, какие задачи можно с ним решить; пиши простым языком»
6. «если пойти по другому — не пытаться прикрутить к их API что-то, а предложить им перепрофилировать своё API на другой сервис? например, не вакансии обрабатывать, а что-то другое — что можно?»
7. «а если вообще от кадрового отказаться? что ещё можно?»
8. «сохрани наше обсуждение в файл, сохрани там отдельно список вопросов, которые я задавал — передам другому агенту в обсуждение»
